# =============================================================================
# Python dependencies for the AI Video Clipper backend + worker.
#
# This file states *ranges* — what the project is compatible with. It is not what a
# build installs. `requirements.lock` holds the exact resolved versions with hashes,
# and that is what the Dockerfile and CI install. Change a range here, then run
# `scripts/lock_requirements.sh` to re-resolve; CI fails if the two disagree.
#
# Every range has an upper bound except one, and that exception is explained where it
# appears. An unbounded requirement means the next major release of a dependency
# arrives in the next `docker build` — untested, unreviewed, and indistinguishable
# from a change of ours.
# =============================================================================

# --- Video / media ---
# 0.2.0 is the last release (2019) and the project is unmaintained; the bound is here so a
# revival with a different API cannot land silently.
ffmpeg-python>=0.2.0,<1.0

# **Deliberately unbounded, and the only one.** yt-dlp's job is to keep working as sites
# change their players, which it does by shipping constantly — often several releases a week,
# each an extractor fix. An upper bound here would cap how new an extractor set a fresh build
# can get, so the pin would gradually stop the tool doing the one thing it is for, and the
# failure would look like "that site is broken" rather than "our pin is stale".
#
# Reproducibility comes from `requirements.lock` instead, which pins it exactly. Bumping it is
# then a deliberate, reviewable act: re-run `scripts/lock_requirements.sh`.
yt-dlp>=2024.7.1

# --- Transcription ---
faster-whisper>=1.0,<2.0

# --- Face tracking / vision ---
# `cv2` comes from mediapipe's own dependency, `opencv-contrib-python` (I7).
#
# Asking for `opencv-python` as well installed *both* wheels, and each ships its own ~91 MB
# directory of near-identical native libraries - so the image carried two OpenCVs, roughly 180 MB
# of it duplicated. `opencv-contrib-python` is a superset of `opencv-python` in the same `cv2`
# namespace, so dropping the explicit pin changes nothing that imports.
#
# The dependency is deliberately left implicit rather than pinned to contrib here: pinning it
# would mean two places to update when mediapipe changes which OpenCV build it wants, and a
# mismatch between them is what produces two wheels again. `worker/effects/reframe.py` uses only
# `VideoCapture`, `CascadeClassifier`, `cvtColor` and `cv2.data` - all core OpenCV, present in
# either build.
mediapipe>=0.10,<1.0
numpy>=1.26,<2.0
Pillow>=10.3,<11.0               # emoji/image compositing

# --- LLM providers (pluggable client) ---
