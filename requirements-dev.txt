# `pip-audit` is deliberately NOT listed here, and that is not an oversight.
#
# It depends on `requests`, and installing `requests` into the environment the suite runs in
# changes yt-dlp's behaviour: yt-dlp prefers its `requests`-based request handler when the package
# is importable, and that handler leaves a socket unclosed. The resulting `ResourceWarning` is
# raised by the garbage collector at an arbitrary later moment, and because `filterwarnings = error`
# turns it into a failure, it lands on whichever test happens to be running. Measured: with
# `requests` present, 3-4 of the `tests/test_url_ingest.py` I13 tests fail non-deterministically
# under `pytest --cov`, and pass without it. Removing `requests` makes the same run green.
#
# So the audit runs in its own isolated environment in CI (see the "Audit Python dependencies"
# step in .github/workflows/ci.yml) rather than being installed alongside the tests. Auditing the
# dependency set must not alter the dependency set it is auditing.
